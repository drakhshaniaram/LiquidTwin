# Implementation Plan: Advanced Pump Hydraulics

**Branch**: `002-advanced-hydraulics` | **Date**: 2026-10-09 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/002-advanced-hydraulics/spec.md`

**Note**: This template is filled in by the `/speckit-plan` command; its definition describes the execution workflow.

## Summary

Extend Stage 1 hydraulics and the versioned terminal document with optional quadratic/tabulated pump curves, bounded deterministic operating-point solving, suction-margin checks, VFD limits, and series/parallel pump trains. Use additive schema version 1.1 while continuing to parse schema 1.0 with the existing constant-head behavior. The Stage 1 oracle for legacy inputs is a hard compatibility gate; curve mode adds operating metrics and exclusions without changing the shared graph representation.

## Technical Context

**Language/Version**: Python 3.12 engine/API; TypeScript 5.9, React 18, Node 20 web

**Primary Dependencies**: Pydantic v2 and JSON Schema codegen; networkx for Stage 1 candidate paths; FastAPI, SQLAlchemy, Alembic, PostgreSQL driver; pytest/hypothesis, Vitest, Playwright. Curve interpolation and bounded root search remain pure engine code; no new numerical solver dependency is required.

**Storage**: PostgreSQL 16 JSONB terminal versions. Schema 1.1 adds optional pump curve, suction, speed-range, and train fields; schema 1.0 remains readable and preserves constant-head results.

**Testing**: pytest + hypothesis for curve validation, calculations, and routing; unchanged feature-001 constant-head oracle suite; a new curve reference fixture; API contract tests; schema codegen check; Vitest/Playwright for pump editing and route metric display.

**Target Platform**: Linux API/database containers and evergreen desktop/mobile browsers. The current web canvas is an SVG prototype; PixiJS remains the constitution-required production target and its performance gate is tracked in feature 001.

**Project Type**: Cross-cutting engine/schema/API/web feature in the existing monorepo; no new deployable service.

**Performance Goals**: Preserve feature-001 route < 1 s and graph build < 200 ms budgets on 500 tanks/5,000 pipes. Tabular curve lookup is O(log n); operating-point search is bounded by declared flow ranges. Large-terminal measurements are not currently available and remain an open release gate.

**Constraints**: Deterministic calculations; flow in m3/h and head in metres; no curve extrapolation; curve mode explicit; per-pump available suction arrives in the route request; preserve constant-head oracle results; every hydraulic exclusion names a machine-readable reason and pump. No SCADA/vendor-catalog integration in this feature.

**Scale/Scope**: Existing terminal-size budgets; request-derived operating points are evaluated for Stage 1 route candidates. CP-SAT Stage 2, live controls, and detailed fluid-property modeling remain out of scope.
